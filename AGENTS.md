# Project guide

Berlin in 3D is a TanStack Start app using React 19, TypeScript, MapLibre GL, PMTiles, Zustand, Tailwind CSS v4, and shadcn/ui.

## Development commands

Use Vite+ (`vp`) for the toolchain. Bun is the package manager behind `vp`; keep `bun.lock` in sync with dependency changes.

| Command | Purpose |
| --- | --- |
| `vp install` | Install dependencies |
| `vp dev` | Start the app at http://localhost:3000 |
| `vp check` | Check formatting and lint rules |
| `vp check --fix` | Format and apply safe lint fixes |
| `vp run typecheck` | Check TypeScript types with `tsc --noEmit` |
| `vp test run` | Run the regression tests once |
| `vp build` | Build the app for production |
| `vp preview` | Serve the production build |
| `vp run generate-routes` | Regenerate the TanStack route tree |
| `vp run tiles:build` | Build optional local Berlin tiles; requires Java 21+ |
| `vp run glyphs:fetch` | Refresh vendored map label glyphs |

Run custom package scripts with `vp run <name>` and local binaries with `vp exec <name>`. Built-in commands such as `vp dev` and `vp build` bypass package scripts. Their settings and worker setup therefore live in Vite config.

## Linting and formatting

`vite.config.ts` is the single configuration for Vite+, Oxlint, and Oxfmt. Ultracite supplies the core, React, anti-slop, React Doctor, and formatting presets; Vite+ runs them. Preserve the documented project overrides there. Use `vp check` and `vp check --fix` instead of the Ultracite CLI.

Type-aware lint rules are opt-in; compiler checks run separately through `vp run typecheck` to preserve the existing lint baseline.

Import Vite APIs from `vite-plus` and future test APIs from `vite-plus/test`. Do not install standalone Vite, Vitest, Oxlint, or Oxfmt versions alongside Vite+. Keep the existing `vite` alias and override: plugins need them to resolve Vite+'s bundled Vite.

## Code conventions

- Use strict types, meaningful names, narrow types at input boundaries, and descriptive `Error` objects. Avoid `any` and unnecessary assertions.
- Keep functions focused, prefer early returns, and use `const` by default. Named function declarations are supported by the project lint overrides.
- Use function components, top-level hooks with complete dependencies, stable list keys, semantic HTML, and accessible labels and controls. React 19 accepts `ref` as a prop.
- Await asynchronous work, handle failures where recovery is possible, and clean up map listeners, timers, workers, and effects.
- Preserve MapLibre's style memoization and avoid allocations in render and pointer-event hot paths. Keep Tailwind and MapLibre CSS in their existing layers.
- Validate external input and avoid unsafe HTML insertion and debug logging in application code.

## Project layout and generated files

- `src/routes/`: TanStack routes; `src/components/map/`: map interface.
- `src/map/`: rendering, themes, sources, search, state, and offline support.
- `src/components/ui/`: shadcn components, excluded from linting as vendored code.
- `src/routeTree.gen.ts`: generated by TanStack Router; do not edit manually.
- `public/maplibre/`: ignored worker files copied by the Vite plugin through `scripts/sync-map-worker.mjs`. Keep this setup working for both dev and builds.
- `public/tiles/berlin.pmtiles`: optional generated local data. The map uses OpenFreeMap when it is absent.

Run `vp check`, `vp run typecheck`, and `vp test run` after changes, and `vp build` for app or build-configuration changes. Import test APIs from `vite-plus/test` and keep tests free of `.only` and `.skip`.
